Everything it does

Fifteen modules, one agent, one licence.

ServerScrub is not a malware scanner with extras bolted on. Each module below covers a different way a shared server actually gets compromised, and they share one database, one schedule and one set of settings.

Detection

Malware scanner

Scans every account on the server, on a schedule you set or on demand.

  • ClamAV where it is installed, plus our own signature and heuristic rules
  • Quarantine keeps the original file, so a false positive is always recoverable
  • Mark a finding as not malware — a verdict tied to the file's exact contents, so the same file is cleared but a changed one is reported again
  • Scans are bounded and refuse to run while a backup is using the same disks

Rootkit scan

Looks for the things a scanner that only reads web directories will never see: altered system binaries, suspicious kernel modules, and processes and ports that do not match what the system reports about itself.

File integrity monitoring

Takes a fingerprint of the files that matter and tells you when one changes. A modified index.php at three in the morning is the earliest warning most compromises give you.

CMS guard

Finds every WordPress, Joomla and Drupal installation on the server and compares each against the current release. Outdated software is how most shared servers are broken into, and this is the list that lets you warn the customer before it happens rather than clean up afterwards.

WordPress database scanner

Infections do not only live in files. This reads the WordPress database for injected options, rogue administrator accounts and malicious scheduled tasks — the parts a file scan walks straight past.

Blocking

Firewall

Integrates with the firewall you already run instead of competing with it.

  • Uses CSF where it is installed, so your existing rules and allow lists stand
  • Falls back to nftables, firewalld or iptables on servers without CSF
  • Blocks carry a deadline and are lifted when it passes
  • Refuses to block a CDN edge or a verified search engine crawler, and says why

Brute force protection

Reads the authentication logs for SSH, FTP, mail and the control panel, and blocks addresses that keep failing. Repeat offenders escalate: a longer block each time, and a permanent one in the end. It reconciles with CSF's own lfd and with cPHulk, so when a block is refused the panel tells you which of them refused it and why — rather than silently showing the address as watched.

Bot shield

Reads the web logs and separates the three kinds of automated traffic that matter: vulnerability scanners probing for known holes, content scrapers taking bandwidth, and exploit attempts against WordPress login and XML-RPC. Each blocked address says which it was and which tool it used.

Flood and scanner detection

Catches the pattern that quietly takes a server down: one address collecting thousands of not-founds across every site looking for secrets, or hammering a single expensive endpoint like xmlrpc.php. On a WordPress host every one of those is a full PHP boot, and a few thousand of them is a load average you cannot explain.

Web application firewall

ModSecurity with the OWASP Core Rule Set, installed and configured for you, with its events collected into the same panel as everything else so you can see what was blocked without reading raw logs.

IP reputation

Checks addresses against public blocklists before they become a problem, and checks your own server's addresses too — so you find out that your IP has been listed from your dashboard, not from a customer whose mail stopped arriving.

Mail

Mail queue

A full view of the exim queue: who is sending, to whom, what the subject is, and why a message is frozen. Search it, read a message, deliver what is stuck and remove what should never have been accepted.

Spam monitor

Watches outbound mail for the shape of a compromised account — a sudden volume from one user, attachments that should not be there — and shows you the account behind it. Finding that before your server's address is listed is the difference between an afternoon and a fortnight.

Hardening and monitoring

PHP hardening

Reviews the PHP configuration for the settings that turn a small bug into a compromised server — dangerous functions left enabled, directory traversal left open — and tells you what to change, with the reason for each.

Real-time monitoring

A lightweight daemon watching for files appearing and changing where they should not, between scheduled scans. It stands aside while backups run, so it never competes with them for the disks.

Log analyser

Turns the logs you never read into the handful of facts worth knowing: what is being attacked, from where, how often, and whether it is getting worse.

A page for every cPanel user

Appears in the Security section of cPanel for every account on the server.

  • Each customer sees the findings for their account and nothing else — enforced by file ownership, not by a filter someone has to remember
  • They can scan their own account, with limits you control, so they stop emailing you to ask
  • The page reaches no server-wide data at all. It cannot.
