Installation

One command, as root.

The installer detects cPanel, installs its dependencies, registers itself in WHM and in every cPanel account, writes its cron entries and starts the first scan.

Before you start

  • cPanel or WHM on a RHEL-family system — AlmaLinux, Rocky, CloudLinux or CentOS
  • Root shell access
  • A licence key from your order

Install

# as root
bash <(curl -fsSL https://serverscrub.com/serverscrub/code/get.sh)

When it finishes, open WHM → Plugins → ServerScrub and enter your licence key. Every cPanel account on the server also gains a ServerScrub Security entry in its own Security section, with no further work.

Update

bash /usr/local/serverscrub/update.sh --yes

Updates overlay the code and preserve everything else: the database, your settings, the quarantine, the logs and any custom signatures. ServerScrub also checks for updates on its own and can apply them for you if you let it.

Check it is running

# what version is installed
grep SG_VERSION /usr/local/serverscrub/backend/config/config.php

# what the scheduler is doing
php /usr/local/serverscrub/backend/cron/scheduler.php --status

Remove

bash /usr/local/serverscrub/uninstall.sh

This removes the application, its cron entries and its WHM and cPanel registrations. The quarantine is deliberately left behind — deleting the evidence of a compromise on the way out is not a decision an uninstaller should make for you. Remove /home/malscan_quarantine yourself once you are satisfied you no longer need it.

If the install cannot reach us

Some servers block outbound access to GitHub, and some block everything except a short allow list. The installer tries our own download host first and falls back to a GitHub mirror, so one being unreachable is not fatal. If both are blocked, allow serverscrub.com on port 443 and run it again.
