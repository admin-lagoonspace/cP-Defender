Questions worth asking first

Is it really unlimited accounts?

Yes. The licence is per server. A server with 300 accounts costs the same as one with 10, because the work ServerScrub does is per server — it scans the disks, reads the logs and manages the firewall once, not once per customer.

What do I need on the server?

cPanel or WHM on a RHEL-family system — AlmaLinux, Rocky, CloudLinux or CentOS. If CSF is installed, ServerScrub uses it; if not, it manages nftables, firewalld or iptables itself.

Will it fight my existing setup?

It is built not to. It uses CSF rather than replacing it, keeps its own rules in a namespaced chain so nothing else is disturbed, reconciles with cPHulk rather than duplicating it, and stands aside while JetBackup or another backup is running rather than competing for the same disks.

What happens to my data when I update?

Nothing. Updates overlay the code and preserve the database, your settings, the quarantine, the logs and any custom signatures. Quarantined files are evidence, and they are never removed by an upgrade.

Can my customers see each other's findings?

No, and not because of a filter that could be got wrong. Each account's report is written into that account's own home directory and owned by that user, so one customer's process cannot open another's. It is impossible by construction.

How do I remove it?

uninstall.sh removes the application, its cron entries and its WHM and cPanel registrations. Your quarantine is left in place, because deleting the evidence of a compromise on the way out is not a decision an uninstaller should make for you.
